# Market Pulse Dashboard: context

Domain context for agents working on this repo. `CLAUDE.md` points here. Where this file and
the code disagree, the code wins and this file is wrong: fix it.

Last verified 2026-08-22.

## What this is

A self-updating trading intelligence dashboard for seven instruments: US30, NAS100, GER40,
AUDUSD, GBPCAD, XAGUSD, XAUUSD. Published to GitHub Pages at
https://digitaldwight.github.io/market-pulse-dashboard/ and embedded at engvision.co/dashboard.

Reports are authored twice a week by an LLM, Sunday 19:30 UTC (weekly) and Wednesday 05:30 UTC
(midweek). Each report is a paired `.md` and `.json` in `reports/`, indexed by `manifest.json`.

Dwight trades off this page. That is the whole reason the correctness bar is where it is.

## The failure mode that matters most

**A stale report with fresh prices is worse than an outage, because it looks current.**

This is not hypothetical. Between 15 July and 22 August 2026 the dashboard showed the 12 July
report's biases, key levels and conviction trades next to live prices. `author.yml` had failed on
all twelve scheduled runs with an Anthropic 400, "credit balance is too low", while `refresh.yml`
kept succeeding because it only pulls yfinance prices and needs no API key. Nothing looked broken.

Gold moved 12.4% and silver 15.5% over that window while the page displayed July levels.

Two consequences for anyone changing this repo:

1. **The price refresh and the report author fail independently.** A green `refresh.yml` says
   nothing about whether the report is current. Check `reports/manifest.json` newest slug against
   today before assuming the pipeline is healthy.
2. **A silent-staleness failure needs to be loud.** If you add a data path, ask what it looks like
   when its upstream dies and the rest keeps running.

## Provider configuration

OpenRouter, OpenAI-wire-compatible, swapped off Anthropic on 2026-08-22.

- Model: `deepseek/deepseek-v4-pro`, set in `author.yml`'s workflow `env` so it can change without
  a code edit. `author_report.py` carries the same default so local runs match CI.
- Secret: `OPENROUTER_API_KEY`. `ANTHROPIC_API_KEY` is dead and can be deleted.
- Cost: about $0.16/run measured, roughly $17/year at twice a week.

### Provider routing is pinned, deliberately

`deepseek/deepseek-v4-pro` is an alias, not an endpoint. OpenRouter fans it out across 17
providers that are not equivalent: quantization ranges fp8 down to fp4, output ceilings range
16,384 to 1,048,576, and output price ranges $0.83/M to $3.83/M for the same model.

`PROVIDER_PREFS` in `author_report.py` pins `quantizations: ["fp8"]`, `require_parameters: true`,
`sort: "price"`.

**Do not remove `require_parameters`.** It is load-bearing. Without it routing lands on StreamLake
at $0.83/M, but StreamLake does not support forced tool calls and every run would fail. It also
excludes DeepInfra, whose 16,384-token output ceiling would truncate a ~30k-token report mid
`publish_report` and surface as an unparseable-JSON error rather than as the routing fault it is.

DeepSeek's first-party endpoint is exposed only on the dated `deepseek-v4-pro-0813` model and is
blocked by the account data policy. Leave that policy alone: first-party DeepSeek retains prompt
data.

### Grounding

Anthropic's `web_search` server tool has no OpenRouter equivalent. Grounding uses OpenRouter's web
plugin, which runs searches server-side and injects results before the model sees them. The model
does not call a search tool and the prompt tells it not to look for one. If you swap provider
again, that prompt wording has to move with it.

`MARKET_PULSE_WEB_SEARCH=0` is for offline schema testing only. Never publish an ungrounded run:
without grounding the model invents economic prints and central-bank headlines, and the scorecard
becomes fiction.

## Scorecard and the record

Each report grades the previous report's biases per instrument as CORRECT, PARTIALLY or WRONG.
`NOT GRADED` exists for one narrow case, a re-baseline after a pipeline outage, and is scoped in
CRITICAL RULE 2 so it cannot become a way to dodge a hard call.

`reports/accuracy.json` is generated by `build_manifest.py` and aggregates every report's
scorecard. It drives the Track Record section. Hit rate counts PARTIALLY as half, and the formula
ships in the payload so it renders on the page rather than sitting implicit in code.

**Known discrepancy.** The reports carry a running record in prose that the model hand-increments
each run. As of 2026-08-22 it reads 61/40/26 across 127 calls, while the record computed from
every scorecard on disk is 65/41/27 across 133. The prose figure has drifted six calls. The
generated file is the one to trust. Not reconciled: the prose record is the model's to correct on
a future run, and overwriting it by hand would hide the drift rather than fix its cause.

## Open finding: the cadence has an NFP hole

Three of the five largest misses landed on payrolls Friday, and NAS100 appears in three of the
five.

| Date | Instrument | Called | Move against |
|---|---|---|---|
| 2026-07-05 | XAGUSD | NEUTRAL_BEARISH | +6.08% |
| 2026-06-07 | NAS100 | BULLISH | -5.55% |
| 2026-07-01 | NAS100 | NEUTRAL_BEARISH | +3.97% |
| 2026-05-20 | GER40 | NEUTRAL_BEARISH | +3.77% |
| 2026-07-05 | NAS100 | NEUTRAL_BULLISH | -3.10% |

Reports publish Sunday and Wednesday. A bias set on Wednesday runs into a Friday print it cannot
see, and the following Sunday grades it as though it were a fair call. That is structural, not bad
luck, and it is the highest-value open problem in this repo. Unresolved as of 2026-08-22.

## Generated files: never hand-edit

`reports/manifest.json` and `reports/accuracy.json` are both written by `build_manifest.py` and
overwritten on every push touching `reports/**`. Edits to them are lost silently.
